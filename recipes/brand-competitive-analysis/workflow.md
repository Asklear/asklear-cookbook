# Brand Competitive Analysis

Asklear capability and query rules: https://dashboard.asklear.cn/docs/agent

## Outcome

交付一份回答“品牌在哪里竞争、相对谁增长、变化由什么驱动”的竞争分析 PPT。

## Inputs

- 品牌名称与已知别名；
- 平台与时间范围；
- 可选的重点品类、竞品和业务问题。

## Workflow

1. **对齐身份**：在每个平台分别确认品牌原始值；有多个候选时抽取代表商品核验，无法确认则请用户选择，不静默合并。
2. **锁定核心品类**：先看品牌整体趋势和品类贡献，再选择最能解释品牌表现的核心品类；记录选择依据。
3. **建立竞争全景**：在相同口径下分析品类趋势、品牌份额、主要竞品和价格结构。跨平台结果分开查询、分别说明实际时间与范围。
4. **验证变化机制**：对增长、降价或结构变化等重要判断补充商品或 SKU 证据。均价变化不能直接写成同款涨跌价；Top N 不能写成完整市场。
5. **生成报告**：先写结论，再展示证据链和策略启示；明确区分 Asklear 指标、计算结果和 Agent 判断，并附查询口径、歧义、缺失和限制。

## Judgment rules

- 品牌别名未充分验证时，跨期缺口只能作为方向性证据。
- 反直觉结论至少需要一项下钻证据支持。
- 份额比较必须使用一致的平台、时间、品类、指标和粒度。
- 数据不支持的问题要明确写成未知，不用常识补造。

## Suggested deck

1. 研究范围与执行摘要；
2. 品牌趋势与核心品类；
3. 品类规模与品牌份额；
4. 竞品与价格结构；
5. 变化机制验证；
6. 策略启示、口径与限制。

## Failure behavior

- 品牌或品类无法可靠对齐时暂停相关分析，请用户确认。
- 查询范围受限时缩小问题或拆分研究，并在报告中说明变化。
- 商品级证据不可用时降低结论强度，不把聚合变化写成已验证机制。
- 部分步骤失败时交付已完成部分，并列出缺口和下一步。
