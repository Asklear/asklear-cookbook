# Brand Competitive Analysis

Asklear capability and query rules: https://dashboard.asklear.cn/docs/agent

## Outcome

回答三个问题：品牌在哪里竞争、相对谁增长、变化由什么驱动。交付 HTML 或 PDF 报告，并在后台保存证据台账。

## Inputs and defaults

唯一必填输入是品牌名称。

未指定时使用以下默认值：

- 问题：品牌在哪里竞争、相对谁增长、变化由什么驱动；
- 平台：当前可访问且能可靠对齐品牌的平台；
- 时间：最近 6 个完整月；不足 6 个月时使用实际完整范围并说明；
- 品类：从品牌销售结构中识别核心品类；
- 竞品：从同品类头部品牌中选择。

只有候选身份会实质改变结果时才请用户选择，不要求用户预先了解品牌别名、平台原始值或类目字段。

## Stage 1: core analysis

1. 分平台对齐品牌原始值，记录纳入与排除项。
2. 查询品牌趋势和品类贡献，锁定核心品类。
3. 在统一的平台、时间、品类、指标和粒度下计算市场规模、品牌份额和主要竞品。
4. 先形成能够回答用户问题的核心判断。

跨平台结果分别查询、分别解释，不直接相加。份额等派生指标保存分子、分母和公式。

## Stage 2: mechanism validation

只对会影响决策的关键判断继续下钻：

- 同一商品的跨期表现；
- 新增、退出或商品链接迁移；
- 价格结构变化；
- 商品或品牌对增量的算术贡献。

不能只凭平均成交价推断同款调价。需要费用确认时，先告诉用户本次下钻要验证什么，再按当前 MCP 流程请求确认。

## Stage 3: optional extension

只有用户明确提出时才扩展到更多平台、更多竞品、非核心品类或额外公开资料。已有证据足以回答问题时停止，不为了填满报告继续查询。

## Evidence rules

- 区分 Asklear 指标、确定性计算和 Agent 判断。
- 每个关键判断至少引用一条证据；反直觉判断必须有下钻证据。
- 每条证据保留实际时间、筛选范围、粒度、数值和限制。
- Top N 不写成全量市场；不完整月份不补零。
- 数据不支持的问题写成未知。

## Deliverable

默认生成一份 HTML 或 PDF，结构固定为：

1. 一句话结论与研究范围；
2. 品牌趋势与核心品类；
3. 市场份额与主要竞品；
4. 增长或下滑机制；
5. 替代解释与未知项；
6. 商业建议；
7. 数据口径、证据与限制。

同时保存符合 `example/run.json` 的证据台账，但不要求普通用户操作校验工具。

## Failure behavior

- 品牌或品类无法可靠对齐时暂停相关分析，请用户确认。
- 数据不足时缩小结论，不擅自替换时间或平台。
- 商品证据不可用时降低机制判断强度。
- 部分步骤失败时交付已完成部分，并列出缺口。
