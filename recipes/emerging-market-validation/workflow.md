# Emerging Market Validation

Asklear capability and query rules: https://dashboard.asklear.cn/docs/agent

## Outcome

判断热门赛道处于“概念热度、早期成交、结构扩散、持续采用”的哪个阶段，并说明证据边界。

## Inputs and defaults

唯一必填输入是市场或产品概念。

未指定时使用以下默认值：

- 问题：判断当前市场阶段；
- 平台：当前可访问且存在可靠零售代理的平台；
- 时间：最近 6 个完整月；不足 6 个月时使用实际完整范围并说明；
- 零售代理：由 Agent 分平台对齐类目、品牌或商品集合；
- 对照市场：只有判断“是否为普遍浪潮”需要时才选择。

只有代理选择会实质改变结论时才请用户确认，不要求用户预先理解平台类目。

## Stage 1: define and align

把“市场火了”拆成四个可证伪问题：

1. 是否出现真实成交增长？
2. 增长是否跨月份、跨平台存在？
3. 增长是否扩散到多个品牌、商品和价格带？
4. 下单是否进一步转化为激活、留存或复购？

分别确认各平台的可观测代理，并记录覆盖与遗漏。名称相似但口径不同的类目不能直接合并。

## Stage 2: core retail validation

1. 比较前后两个完整时期的成交额、销量和平均成交价。
2. 检查逐月形态，排除只有单月峰值的情况。
3. 检查品牌集中度，判断增长是否只属于少数参与者。
4. 形成初步阶段判断。

单月大促峰值不能单独证明趋势；不完整月份不补零；跨平台绝对规模不相加。

## Stage 3: mechanism validation

只对会改变阶段判断的部分继续下钻：

- 核心商品跨期表现；
- 新增、退出和商品链接迁移；
- 价格结构；
- 商品或品牌对增量的算术贡献；
- 相邻市场是否同向变化。

商品贡献是算术归因，不是因果归因。需要费用确认时，先说明下钻要排除哪种替代解释，再按当前 MCP 流程请求确认。

## Stage 4: adoption boundary

如果具备网页研究或其他外部证据能力，核对新品、大促、出货、激活、退货、留存和使用场景。没有这些证据时，结论最多达到“早期成交”或“结构扩散”，不能写成“持续采用”。

已有证据足以回答问题时停止，不为了证明预设叙事继续查询。

## Stage decision

- **概念热度**：有讨论，缺少稳定成交证据；
- **早期成交**：成交增长可观察，但集中、短期或不稳定；
- **结构扩散**：更多月份、品牌、商品或价格带共同增长；
- **持续采用**：除成交外，还有激活、留存、复购或持续使用证据。

## Evidence rules

- 区分 Asklear 指标、确定性计算、外部来源和 Agent 判断。
- 派生事实保存公式和输入事实 ID。
- 跨平台或跨品类结论记录可比性判断。
- 每个关键判断引用事实 ID；标题样本和 Top N 不外推到全市场。
- 报告必须写出什么证据会改变当前结论。

## Deliverable

默认生成一份 HTML 或 PDF，结构固定为：

1. 当前阶段与一句话结论；
2. 研究代理与实际范围；
3. 量、额、价和月度形态；
4. 品牌与商品增量来源；
5. 平台差异或相邻市场对照；
6. 替代解释、反证条件和未知项；
7. 商业含义与下一步指标；
8. 数据口径、证据与限制。

同时保存符合 `example/data.json` 的证据包，但不要求普通用户操作校验工具。

## Failure behavior

- 代理类目无法可靠对齐时暂停，请用户确认。
- 只有单月或不完整数据时，不宣称形成趋势。
- 商品或品牌证据不足时，把结论降级为类目层观察。
- 缺少使用和留存数据时，不写成“持续采用”。
